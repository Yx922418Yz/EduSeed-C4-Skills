# LiYaxuan C4D 拿来说明

## 这个技能/成果是从哪里"拿来"的

C4D 的核心是"拿来主义 + 本地化落地"。我的素材来源与改造说明如下：

## 1. 技术栈（按挑战官方推荐选择）

| 组件 | 来源 | 我的选择与理由 |
|------|------|----------------|
| 模型 | Google 官方发布的开源 **Gemma 4**（Apache 2.0） | E4B（~4.5B 活跃参数）：官方推荐"普通笔记本入门"档，适配我的 RTX 5060 8GB 显存 |
| 运行器 | 挑战 PDF「推荐技术栈」表格 | **Ollama**（难度★，一行命令跑起来，自带 OpenAI 兼容 API）——完全按官方推荐 |
| GGUF 文件 | unsloth/gemma-4-E4B-it-GGUF（社区量化） | Q5_K_M：质量/体积平衡（5.5GB），8GB 显存可全量加载 |
| 地图库 | 挑战 PDF「生成交互式地图的方式」表格 | **Folium**（Python 最简单交互式地图）——完全按官方推荐 |

## 2. 代码的"拿来"与改造

| 部分 | 来源 | 改造 |
|------|------|------|
| 整体流程 | C4D.pdf「最简示例」：`requests.post` 本地 API → 解析 JSON → Folium 生成地图 | 扩展为完整 Agent：函数调用工具 + 多轮对话 + 工具结果回填 + 降级路径 + 全程留痕 |
| 地图渲染 | 官方示例的 `folium.Marker(popup=..., tooltip=...)` | 增加分组图标、popup 含坐标与描述、地图标题、平均坐标定位 |
| 坐标知识库 | 官方示例让模型"List 8 notable locations"但坐标靠模型输出 | **改造点**：坐标改为函数调用查询真实 POI（高德地图/河南省机场集团/卫星地图，2026-10 逐条查证），杜绝 LLM 幻觉坐标 |

## 3. 明确不是拿来（原创部分）

1. `gemma_agent.py` 的 **Agent 循环**：函数调用执行器、JSON 稳健提取、12 轮重试、双路径降级；
2. `verify_output.py` 校验器：结构/坐标范围/含西亚斯/非手写四重校验；
3. `places_kb.json` 坐标知识库：8 个地点的真实经纬度逐条联网查证并标注来源；
4. 全程 `agent_trace.json` 留痕机制——评审可逐条追溯"模型确实生成了数据"。

## 4. 为什么坐标不直接让模型写

4B 级模型对精确经纬度的记忆不可靠（幻觉风险高）。挑战要求"数据由模型生成"
并"通过函数调用或结构化输出"——我的设计让模型**选择地点、撰写描述、决定调用哪些工具**，
坐标由函数调用返回真实数据。这正是 Agent 该有的样子：**模型做决策，工具给事实**。

## 5. 环境适配记录

- Ollama 官方安装包直下极慢（约 2MB/30s 停滞）→ 改用 winget 安装（1.58GB 秒下）；

  直连 unsloth GGUF（5.11GB）+ Modelfile 本地导入；
- 这些都如实记录在 AI 日志中。
