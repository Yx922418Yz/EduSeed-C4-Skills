## 五、真实性与防幻觉说明（诚实记录）

1. **地点选择与描述**：由本地 Gemma 4 E4B 生成（agent_trace.json 可见模型原始输出）；
2. **坐标**：一律来自 `get_place_coordinates` 工具（真实 POI 知识库，逐条联网查证）；
3. **防幻觉机制**：最终汇总前做坐标核对，模型曾对知识库外地点输出自拟坐标

   无法核实的条目不入地图并在 trace 中记录（本次运行 8/8 全部核实）。

## 六、失败与修复记录（节选，完整见 AI 日志）

| 问题 | 根因 | 修复 |
|------|------|------|
| 官方仓库 pull 的模型报 500 | GGUF blob 损坏（duplicate tensor） | 改 ModelScope 直连下载 + Modelfile 导入 |
| Agent 两条路径失败 | Ollama 返回的 arguments 是 dict，`json.loads(dict)` 报错致参数为空 | 增加 parse_args 兼容 str/dict |
| 模型持续调用工具不出最终 JSON | 工具循环与汇总输出耦合 | 重构为两阶段：先收集坐标 → 新对话输出 JSON |
| 模型自拟坐标 | 4B 模型对精确经纬度记忆不可靠 | 坐标核对 + 修正轮 + 未核实条目不入地图 |
| OSM 底图不显示 | 本机网络无法访问 OSM 瓦片 | 改用高德瓦片（国内可达） |
| 桌面截图拍到锁屏 | 电脑已锁屏 | 用 Chrome headless 截图 + nvidia-smi/ollama ps 文本证据 |
