# C4D 方案设计：本地大模型 Agent + 交互式地图（LiYaxuan）

## 一、挑战要求（C4D 主路径）

1. 在本地设备下载并运行 Gemma 4 模型；
2. 用本地模型驱动 Agent 技能——执行**函数调用**、生成**结构化输出**、完成**多步任务**；
3. 生成**交互式地图**（可缩放、可点击标记），展示 SIAS University（郑州西亚斯学院）周边；
4. 截图/录屏证明是在本地跑的（评审关键信息：模型 + 量化方式 + 设备）。

> 说明：C4D 补充说明中"三步完成法"面向**非计算机专业**同学；本人为软件工程专业，
> 按 C4D 主挑战（硬核分支：Agent + 函数调用 + 交互地图）完成。

## 二、模型与环境（评审关键信息）

| 项 | 值 |
|----|-----|
| 模型 | **Gemma 4 E4B**（~4.5B 活跃参数） |
| 量化 | **Q5_K_M**（GGUF，5.5 GB） |
| 运行方式 | 本地 **Ollama** v0.35.1（OpenAI 兼容 API），无任何云端 API 费用 |
| 设备 | **NVIDIA GeForce RTX 5060 Laptop GPU**（8GB 显存，CUDA），Intel i9-14900HX / 32GB 内存 |
| 操作系统 | Windows 11 |

## 三、架构

```
用户指令："给我生成一个 SIAS University 周边的地图"
        │
        ▼
┌─────────────────────────────────────────────┐
│ 本地 Gemma 4 E4B（Ollama /api/chat + tools）│  ← 模型在本地运行
└─────────────────────────────────────────────┘
        │ ① 函数调用：get_place_coordinates(地点名)  ← 工具调用能力
        ▼
┌─────────────────────────────────────────────┐
│ 工具执行器（scripts/gemma_agent.py）          │  ← 查询真实坐标知识库
│ references/places_kb.json（高德/机场集团等来源）│
└─────────────────────────────────────────────┘
        │ ② 坐标回填给模型
        ▼
本地模型汇总 → ③ 结构化输出 JSON 数组（name/name_zh/lat/lng/description）
        │        ▲
        │        └── ②' Agent 记忆：坐标快照写入 sias_memory.json，
        │              阶段二从记忆读取（长期记忆，跨会话复用）
        ▼
┌─────────────────────────────────────────────┐
│ build_map.py → Folium 交互地图 sias_map.html  │  ← Leaflet：缩放/点击弹窗
└─────────────────────────────────────────────┘
        │
        ▼
浏览器打开 → 截图（output_screenshots/）→ 验证（verify_output.py）
```

## 四、Agent 能力设计（对应挑战要求）

| 挑战要求 | 设计 | 证据 |
|----------|------|------|
| 函数调用（function calling） | 工具 `get_place_coordinates(name)`；模型自主决定调用 | agent_trace.json 中的 tool_calls 轮次 |
| 多步推理 | 先挑选地点 → 逐点查坐标 → 汇总 JSON | 对话轨迹轮次 |
| 结构化输出 | 最终只输出 JSON 数组（严格字段） | sias_places.json |
| 记忆（长期记忆） | 阶段一坐标快照持久化 `sias_memory.json`，阶段二"从记忆读取"，跨会话复用 | sias_memory.json + verify 记忆校验 |
| 地点数据由本地模型生成 | 地点选择 + 中文描述由 Gemma 4 生成 | trace 中的 model 输出 |
| 坐标准确性 | 坐标来自工具查询的真实 POI 知识库（**防止 LLM 幻觉坐标**——地图坐标必须可验证） | places_kb.json 每点带来源 |

**设计权衡（诚实说明）**：挑战要求"地点数据由模型生成（不是你手写的 JSON）"。
本设计让**地点选择与文字描述**由模型生成，**经纬度**由模型通过函数调用从
已验证知识库获取——既满足"模型通过函数调用生成地图数据"，又保证地图不因
LLM 幻觉坐标而失真。坐标知识库来源：高德地图 POI、河南省机场集团、卫星地图数据（2026-10 查证）。

## 五、降级路径（稳妥设计）

若模型在极端情况下不触发函数调用，自动降级为**结构化输出 + 工具补全坐标**：
模型仍生成地点与描述（满足"结构化输出"要求），坐标由工具回填；
两种模式都会在 agent_trace.json 中标注，评审可追溯。

## 六、验证方案

| 验证项 | 方法 |
|--------|------|
| 模型本地运行 | `ollama ps` / API 响应 / 截图（任务管理器 + 模型名） |
| 函数调用发生 | agent_trace.json 含 tool_calls 与工具结果 |
| JSON 结构 | verify_output.py：字段齐全、坐标在中国范围、含西亚斯 |
| 地图交互 | 浏览器打开 sias_map.html，缩放 + 点击标记截图 |
| 非手写证明 | trace 完整保留模型原始输出与工具调用序列 |

## 七、风险与对策

| 风险 | 对策 |
|------|------|
| Ollama 仓库拉取慢/损坏 | 改用 hf-mirror 直连 GGUF + Modelfile 本地导入 |
| 4B 模型函数调用不稳定 | 结构化输出降级路径 + 强系统提示 + 最多 12 轮重试 |
| 显存不足 | num_ctx 4096，Q5_K_M 5.5GB 适配 8GB 显存 |
