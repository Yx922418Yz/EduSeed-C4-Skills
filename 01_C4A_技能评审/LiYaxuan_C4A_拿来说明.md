## 四、为什么这样改（取舍分析）

1. **为什么保留 wechat-doc-mapper 的骨架而不是重写？**
   "拿来 → 理解 → 改造 → 超越"是 C4A 的核心训练目标。它的采集与识别链已经过 9 文件实测验证，
   重写同样的逻辑是浪费——评审器真正的新价值在"阅卷"（完整性 + 质量），不在"分信"。

2. **为什么完整性检查用三通道信号而不是只查文件名？**
   同学命名可能不规范（如把 skill说明写成"说明.md"）。文件名通道 + 内容信号通道 + 扩展名偏好通道，
   覆盖率更高且每一条命中都可审计。

3. **为什么质量评审用 check item 谓词化而不是关键词计数？**
   关键词计数会误报（"AI 工具"出现在任何文档里）；把 rubric 的每个 check item 翻译成可计算谓词后，
   评分依据是人可读的英文检查项，透明、可复核、可配置。

4. **为什么把"可执行内容"做成专项检测？**
   因为"skill说明.md"文件名含 skill 会被文件名通道误判为可执行内容——真实 .skill/.py 文件应该优先。
   这是迭代中真实踩坑后加的规则（见 AI 日志第 3 轮）。

5. **为什么选"规则 + LLM 混合"而不是纯 LLM？**
   见方案设计第四节：完整性的客观事实必须零误判（纯规则），质量判断需要可复现（规则打分 + LLM 补充点评），
   且不配置 API 时技能必须仍能完整运行（离线可用 = 可复用性）。

## 五、与 c4-skill-evaluator-starter 的关系

starter 提供了 SKILL.md 脚手架和 c4_rubric.yaml 信号库（5 项交付物 + 4 条件 + 评分公式）。
本技能：**直接采用**其 c4_rubric.yaml 作为评分规则（拿来），**实现**了它要求的全部逻辑
（"What You Need to Build" 列表：扫描逻辑、完整性检查器、质量评审器、报告生成器、真实测试），
并在报告模板基础上新增班级总览统计与版本追踪。
