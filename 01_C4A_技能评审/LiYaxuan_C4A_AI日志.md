**产出：** 方案设计文档初稿 + 系统架构图。

### Day 1 下午 —— 改造与开发（迭代 4 轮）

**第 1 轮：** 让 AI 基于 wechat_doc_mapper.py 生成 c4_skill_evaluator.py 骨架。
- Prompt 要点："保留 inventory_folder 和作者识别链，新增完整性检查、四条件评审、报告生成"
- 结果：骨架完成，但运行报 2 个 bug。

**第 2 轮（bug 修复）：**
- Bug 1：所有文件被误判为非 C4 —— 原因是 C4 过滤发生在作者解析之前，`c4_hint` 全是 None；
  修复：先 parse_filename 再过滤。
- Bug 2：`ValueError: could not convert string to float: 'completeness_score'` —— 评分公式解析失败；
  修复：权重直接取 rubric 约定的 0.4 / 0.6 常量。

**第 3 轮（检测质量修复）：**
- 问题：`可执行内容`误匹配到"skill说明.md"（文件名含 skill）；AI日志误匹配到附带提及 Claude 的文档；
- 修复：可执行内容优先真实可执行文件（.skill/.py）；其余交付物存在文件名精确命中时优先采用文件名命中；
- 同时处理：语料中残留技能源目录被误判为独立作者 → 生成器打包后清理。

**第 4 轮（边界处理）：**
- 问题：目录说明文件（README）被内容信号误收为提交；
- 修复：README 类文件名在 C4 候选过滤时直接排除；非规范命名文件按内容信号回退进入 Unknown 桶。

**我的动作（非 AI 部分）：**
- 构造测试语料：2 份课程材料真实技能 + 3 份模拟提交（完整/部分/缺失三档）+ 非 C4 文件；
- 每次修复后重跑全量语料验证（5 作者 / 3 完整 / 1 部分 / 1 缺失）。

## 四、失败经验与反思

1. **"先过滤后解析"的顺序错误**是新手常见 bug：数据管道里字段填充顺序必须与消费顺序一致；
2. **关键词信号必然有误报**（"skill说明"含 skill → 被当可执行内容）：信号设计要用"真实文件优先 + 精确命中优先"缓解，而不是堆更多关键词；
3. **测试语料比代码更难**：构造"完整/部分/缺失/不规范/无关"五档数据花的时间超过写评审器本身——这让我理解评审系统真正的难点是边界覆盖；
4. **AI 日志必须诚实记录失败**：本日志记录的 3 个 bug 都是真实调试过程，没有事后美化。
